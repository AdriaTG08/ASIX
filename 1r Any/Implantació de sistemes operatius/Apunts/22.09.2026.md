# Apunts: Implantació de Sistemes Operatius — Fonaments (1r ASIX)

## 1. Què és un Sistema Operatiu (SO)

**Sistema Operatiu:** programari que actua d'**intermediari entre el maquinari i l'usuari/aplicacions**, gestionant els recursos de l'ordinador (CPU, memòria, disc, perifèrics) i oferint una interfície per utilitzar-los.

**Funcions principals:**

| Funció | Descripció |
|---|---|
| Gestió de processos | Decidir quins programes s'executen i quan |
| Gestió de memòria | Assignar i alliberar espai a la RAM |
| Gestió d'E/S i fitxers | Controlar perifèrics i organitzar la informació al disc |
| Interfície d'usuari | Permetre interactuar amb el sistema (CLI, escriptori...) |

> Idea clau: sense SO, cada programa hauria de saber controlar directament el maquinari (com es feia antigament) — el SO estalvia aquesta complexitat i evita que els programes es "trepitgin" entre ells.

## 2. Gestió de processos

**Procés:** programa **en execució**, amb els seus propis recursos assignats (memòria, dades, estat).

> Diferència clau: un **programa** és un fitxer estàtic al disc (codi); un **procés** és aquell programa carregat i executant-se, amb estat propi.

### Estats d'un procés

```
   Nou → Preparat (Ready) ⇄ Execució (Running) → Finalitzat
                ↑                    ↓
                └──── Bloquejat (Waiting) ────┘
```

| Estat | Significat |
|---|---|
| **Nou** | Acabat de crear |
| **Preparat** | Esperant que la CPU l'atengui |
| **Execució** | Fent servir la CPU ara mateix |
| **Bloquejat** | Esperant un recurs (ex: dades d'un disc, entrada de teclat) |
| **Finalitzat** | Ha acabat d'executar-se |

**Planificador (scheduler):** part del SO que decideix **quin procés s'executa i quan**, ja que normalment hi ha més processos que nuclis de CPU disponibles (multitasca).

## 3. Process Control Block (PCB)

**PCB:** estructura de dades interna del SO que **guarda tota la informació d'un procés concret**, necessària perquè el SO pugui gestionar-lo i, si cal, aturar-lo i reprendre'l més tard sense perdre el seu estat.

**Camps típics d'un PCB:**

| Camp | Contingut |
|---|---|
| **PID** | Identificador únic del procés |
| **Estat** | Preparat, execució, bloquejat... |
| **Comptador de programa (PC)** | Adreça de la següent instrucció a executar |
| **Registres de CPU** | Valors guardats dels registres en aquell moment |
| **Informació de memòria** | Punters a les zones de memòria assignades |
| **Prioritat** | Per ajudar el planificador a decidir |
| **Recursos assignats** | Fitxers oberts, dispositius en ús... |

> Analogia: el PCB és com una **fitxa de "punt de guardat"** d'un videojoc — guarda tot el necessari perquè, quan la CPU torni a aquest procés (després d'atendre'n uns altres), pugui continuar exactament on ho havia deixat.

## 4. Gestió de la memòria

El SO s'encarrega de **repartir la memòria RAM** entre el propi SO i tots els processos en execució, assegurant que:
- Cada procés tingui l'espai que necessita.
- Un procés **no pugui accedir** a la memòria d'un altre (aïllament/seguretat).

**Conceptes clau:**

| Concepte | Descripció |
|---|---|
| **Memòria virtual** | Tècnica que simula tenir més RAM de la física real, usant part del disc com a extensió |
| **Paginació** | Divideix la memòria en blocs fixos (pàgines) per gestionar-la de forma més flexible |
| **Swap** | Espai al disc que s'utilitza quan la RAM s'omple, per "treure" temporalment dades poc usades |

> Idea clau: sense una bona gestió de memòria, un procés podria escriure sobre les dades d'un altre i fer petar el sistema — el SO evita això assignant zones separades i controlades.

## 5. Gestió d'entrada/sortida (E/S)

El SO controla la comunicació amb els **perifèrics** (teclat, ratolí, disc, impressora, xarxa...) mitjançant:

| Element | Funció |
|---|---|
| **Drivers** | Programes que "tradueixen" entre el SO i el maquinari específic de cada dispositiu |
| **Buffers** | Zones de memòria temporal per compensar diferències de velocitat entre CPU i perifèrics |
| **Interrupcions** | Senyals que envia un dispositiu a la CPU per avisar que necessita atenció (en lloc que la CPU estigui preguntant constantment) |

> Idea clau: gràcies a les interrupcions, la CPU no "espera activament" que un dispositiu lent (com un disc) acabi — pot fer altres tasques mentrestant i ser avisada quan calgui.

## 6. Sistema de fitxers (File System)

Estructura que organitza **com es guarden, s'anomenen i es localitzen les dades** dins d'un dispositiu d'emmagatzematge (disc dur, SSD...).

**Elements bàsics:**

| Element | Descripció |
|---|---|
| **Fitxer** | Unitat bàsica d'emmagatzematge (un document, un programa...) |
| **Directori/Carpeta** | Agrupació organitzativa de fitxers |
| **Metadades del fitxer** | Nom, mida, data de creació/modificació, permisos... |
| **Sistema de fitxers (exemples)** | NTFS (Windows), ext4 (Linux), APFS (macOS) |

> Idea clau: el sistema de fitxers és el que permet que, quan dius "obre el fitxer X", el SO sàpiga exactament **on** estan físicament aquestes dades al disc i com reconstruir-les correctament.

---

**Idea clau general:** el SO gestiona quatre grans recursos (processos, memòria, E/S i fitxers) de manera coordinada; el **PCB** és la peça central que permet al SO "recordar" l'estat de cada procés per repartir la CPU entre tots ells sense perdre informació, fent possible la multitasca.

Paraules clau: Sistemes operatius, gestió de processos, gestió de la memòria, gestió d'entrada i sortida i sistema d'arxius, process control bloc (PCB).
