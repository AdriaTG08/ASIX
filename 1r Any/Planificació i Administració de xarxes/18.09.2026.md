# Apunts: Xarxes — Comunicació Horitzontal, PDU i Model TCP/IP (1r ASIX)

## 1. Comunicació horitzontal vs vertical

Dins del model OSI (o TCP/IP), la comunicació es pot entendre en dos sentits:

| Tipus | Descripció |
|---|---|
| **Comunicació vertical** | Pas de dades **entre capes diferents del mateix dispositiu** (ex: de la capa Transport a la capa Xarxa, dins del mateix ordinador) |
| **Comunicació horitzontal** | Comunicació **lògica entre la mateixa capa** de dos dispositius diferents (ex: la capa Transport de l'emissor "parla" amb la capa Transport del receptor) |

> Idea clau: la comunicació horitzontal és **virtual/lògica**, no física — en realitat les dades sempre baixen fins a la capa física, viatgen pel cable, i tornen a pujar a l'altre extrem. Però conceptualment, cada capa "es comunica" amb la seva equivalent a l'altre dispositiu (gràcies a les capçaleres que afegeix cada capa, que només entén la seva capa bessona).

```
Emissor                          Receptor
Capa Transport  ←--- horitzontal ---→  Capa Transport
      ↓ vertical                            ↑ vertical
Capa Xarxa      ←--- horitzontal ---→  Capa Xarxa
      ↓                                     ↑
Capa Física     -------- cable -------→  Capa Física
```

## 2. PDU (Protocol Data Unit)

**PDU** = unitat de dades que es transmet a cada capa, formada per les **dades + la capçalera (i a vegades peu)** que afegeix aquella capa.

Cada capa té el seu propi nom per a la PDU:

| Capa (OSI) | Nom de la PDU |
|---|---|
| Aplicació/Presentació/Sessió | **Dades** (Data) |
| Transport | **Segment** (TCP) / **Datagrama** (UDP) |
| Xarxa | **Paquet** |
| Enllaç | **Trama** (Frame) |
| Física | **Bits** |

> Idea clau: a mesura que les dades baixen per les capes, cada capa **encapsula** la PDU anterior afegint-hi la seva pròpia capçalera → per això cada capa té un nom diferent per a "el mateix paquet de dades", segons quantes capçaleres porta ja afegides.

## 3. Model TCP/IP

Versió més pràctica i simplificada del model OSI (4 capes en lloc de 7), és el model que realment fa servir Internet.

| Capa TCP/IP | Equivalent a OSI | Funció | Exemples |
|---|---|---|---|
| **Aplicació** | Aplicació + Presentació + Sessió | Interfície amb l'usuari/programes | HTTP, FTP, DNS, SMTP |
| **Transport** | Transport | Comunicació extrem a extrem | TCP, UDP |
| **Internet** | Xarxa | Adreçament i encaminament | IP, ICMP, ARP |
| **Accés a la xarxa** | Enllaç + Física | Transmissió física i control d'accés al medi | Ethernet, Wi-Fi |

**Comparativa visual:**

```
   OSI (7 capes)              TCP/IP (4 capes)
   Aplicació      ┐
   Presentació    ├──────→    Aplicació
   Sessió         ┘
   Transport      ───────→    Transport
   Xarxa          ───────→    Internet
   Enllaç         ┐
   Física         ┴──────→    Accés a la xarxa
```

## 4. Subnivell MAC / LLC (dins la capa d'Enllaç)

La capa d'Enllaç (capa 2 d'OSI) es divideix realment en **dos subnivells**:

| Subnivell | Nom complet | Funció |
|---|---|---|
| **LLC** | Logical Link Control | Controla la comunicació lògica: gestiona errors, control de flux i identifica quin protocol de capa superior porta la trama (independent del tipus de xarxa física) |
| **MAC** | Media Access Control | Controla **l'accés al medi físic**: gestiona les adreces MAC i decideix com/quan pot transmetre cada dispositiu (evitar col·lisions) |

```
Capa 2 (Enllaç)
   ┌─────────────┐
   │     LLC     │  ← independent del medi físic (IEEE 802.2)
   ├─────────────┤
   │     MAC     │  ← depèn del tipus de xarxa (Ethernet 802.3, Wi-Fi 802.11...)
   └─────────────┘
```

> Idea clau: el **LLC** és la part "genèrica" que permet que diferents tecnologies de xarxa (Ethernet, Wi-Fi, Token Ring...) es comuniquin amb les capes superiors de la mateixa manera; el **MAC** és la part "específica" que s'encarrega de com es comparteix físicament el medi i gestiona les adreces MAC (les que identifiquen cada targeta de xarxa de forma única).

---

**Idea clau general:** el model TCP/IP simplifica OSI en 4 capes pràctiques; a cada capa, les dades viatgen encapsulades com una PDU diferent; i tot i que la comunicació sembla "horitzontal" entre capes iguals de dos dispositius, físicament sempre baixa i puja per totes les capes fins arribar al medi (on entra en joc la divisió MAC/LLC per gestionar l'accés compartit).

**Paraules clau:** Comunicació horitzontal, PDU, Model TCP/IP Subnivell MAC / LLC.
