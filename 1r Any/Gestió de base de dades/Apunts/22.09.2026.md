# Apunts: Gestió de Bases de Dades — SGBD i Model E-R (1r ASIX)

## 1. Sistema Gestor de Base de Dades (SGBD)

**SGBD (DBMS en anglès):** programari que permet **crear, gestionar i consultar** bases de dades, fent de capa intermèdia entre l'usuari/aplicacions i les dades emmagatzemades físicament.

**Exemples de SGBD:** MySQL, PostgreSQL, Oracle, SQL Server, SQLite.

**Funcions principals d'un SGBD:**

| Funció | Descripció |
|---|---|
| Definir l'estructura | Crear taules, relacions, tipus de dades |
| Manipular les dades | Inserir, modificar, eliminar, consultar |
| Controlar l'accés | Gestionar permisos i usuaris |
| Garantir la integritat | Evitar dades inconsistents o duplicades |
| Gestionar concurrència | Permetre múltiples usuaris alhora sense conflictes |

> Idea clau: sense un SGBD, cada aplicació hauria de gestionar directament els fitxers de dades — el SGBD centralitza aquesta feina i ofereix garanties (seguretat, integritat, accés simultani) que seria molt difícil programar manualment cada vegada.

## 2. Independència física i lògica

Un dels avantatges clau d'un SGBD és que separa **com es veuen les dades** de **com estan realment emmagatzemades**.

| Tipus | Definició | Exemple pràctic |
|---|---|---|
| **Independència lògica** | Es pot modificar l'estructura lògica (ex: afegir una taula o un camp) **sense afectar** les aplicacions que ja funcionen | Afegir la columna `email` a la taula `Alumne` sense trencar el programa que ja consultava `nom` i `edat` |
| **Independència física** | Es pot canviar **com s'emmagatzemen físicament** les dades (disc, índexs, organització) **sense afectar** la vista lògica ni les aplicacions | Canviar l'organització d'indexada a seqüencial, o migrar de disc, sense que l'usuari ho noti |

> Idea clau: gràcies a aquesta separació, els programadors treballen amb les dades "des de dalt" (taules, consultes) sense preocupar-se de com estan guardades realment "a baix" (fitxers, blocs de disc).

## 3. Redundància

**Redundància:** repetició innecessària de la mateixa dada en diversos llocs de la base de dades.

**Problemes que causa:**
- Ocupa més espai del necessari.
- Risc d'**inconsistència**: si actualitzes una còpia i no l'altra, les dades deixen de coincidir.

**Exemple:**
```
❌ Sense normalitzar (redundant):
Taula COMANDA: id_comanda | nom_client | adreça_client | producte
→ Si un client fa 10 comandes, el seu nom i adreça es repeteixen 10 vegades

✅ Normalitzat (sense redundància):
Taula CLIENT: id_client | nom | adreça
Taula COMANDA: id_comanda | id_client (FK) | producte
```

> Idea clau: un bon disseny de BD (normalització) busca **minimitzar la redundància**, tot i que a vegades se n'introdueix una mica de manera controlada per millorar el rendiment (desnormalització).

## 4. Transacció

**Transacció:** conjunt d'operacions sobre la BD que es tracten com **una unitat indivisible** — o es fan totes, o no se'n fa cap.

**Propietats ACID** (les ha de complir tota transacció):

| Propietat | Significat |
|---|---|
| **Atomicitat** | Tot o res — si falla un pas, es desfà tot (rollback) |
| **Consistència** | La BD passa d'un estat vàlid a un altre estat vàlid |
| **Aïllament (Isolation)** | Una transacció no interfereix amb una altra que s'executa alhora |
| **Durabilitat** | Un cop confirmada (commit), els canvis persisteixen encara que hi hagi una fallada |

**Exemple clàssic:** una transferència bancària (treure diners d'un compte i posar-los a un altre) — si falla després de treure'ls però abans de posar-los, **tota** l'operació s'ha de desfer.

## 5. Concurrència

**Concurrència:** capacitat del SGBD de permetre que **múltiples usuaris/processos accedeixin a la BD alhora** sense que es produeixin errors ni inconsistències.

**Problemes que ha de resoldre el SGBD:**

| Problema | Descripció |
|---|---|
| **Pèrdua d'actualitzacions** | Dos usuaris modifiquen la mateixa dada alhora i un sobreescriu l'altre |
| **Lectures brutes** | Un usuari llegeix dades que un altre encara no ha confirmat (i després es desfan) |

**Solució:** el SGBD fa servir **bloquejos (locks)** per controlar l'accés concurrent a les mateixes dades.

## 6. Seguretat

Mecanismes per protegir la BD contra accessos no autoritzats o pèrdua de dades:

| Mecanisme | Funció |
|---|---|
| **Autenticació** | Verificar qui és l'usuari (usuari/contrasenya) |
| **Autorització/permisos** | Definir què pot fer cada usuari (llegir, escriure, esborrar...) |
| **Còpies de seguretat (backups)** | Recuperar dades en cas de fallada |
| **Xifrat** | Protegir les dades sensibles |

## 7. SQL i les seves subllengües

**SQL (Structured Query Language):** llenguatge estàndard per interactuar amb bases de dades relacionals.

Es divideix en diversos subconjunts segons la funció:

| Subllenguatge | Nom complet | Funció | Ordres típiques |
|---|---|---|---|
| **DDL** | Data Definition Language | Definir l'**estructura** de la BD | `CREATE`, `ALTER`, `DROP` |
| **DML** | Data Manipulation Language | **Modificar** les dades | `INSERT`, `UPDATE`, `DELETE` |
| **DQL** | Data Query Language | **Consultar** les dades | `SELECT` |

**Exemple de cada un:**
```sql
-- DDL: crear l'estructura
CREATE TABLE Alumne (id INT PRIMARY KEY, nom VARCHAR(50));

-- DML: modificar dades
INSERT INTO Alumne VALUES (1, 'Adrià');

-- DQL: consultar dades
SELECT nom FROM Alumne WHERE id = 1;
```

> Idea per recordar: **DDL defineix l'"esquelet"**, **DML mou/canvia la "carn"** (les dades), **DQL només mira** sense tocar res.

## 8. Model Entitat-Relació (E-R)

Model conceptual (vist també a l'apunt anterior) per representar gràficament la realitat abans de crear les taules.

**Elements bàsics:**

| Element | Símbol típic | Descripció |
|---|---|---|
| **Entitat** | Rectangle | Objecte del món real (`Alumne`, `Curs`) |
| **Atribut** | El·lipse | Propietat d'una entitat (`nom`, `edat`) |
| **Relació** | Rombe | Connexió entre entitats (`Matricula`) |
| **Cardinalitat** | Nombres a la relació (1:1, 1:N, N:M) | Quantes instàncies d'una entitat es relacionen amb quantes de l'altra |

**Exemple:**
```
[Alumne] ---- (Matricula) ---- [Curs]
   1                N   N            1
```
Un alumne es pot matricular a diversos cursos, i un curs pot tenir diversos alumnes → relació **N:M**.

---

**Idea clau general:** un SGBD no és només "on es guarden les dades" — ofereix garanties fonamentals (independència, no-redundància, transaccions ACID, concurrència i seguretat) que fan que treballar amb la BD sigui fiable encara que hi hagi molts usuaris alhora; i SQL (amb DDL/DML/DQL) és l'eina estàndard per interactuar-hi, partint sempre d'un model E-R ben dissenyat.

Paraules clau: Sistema gestor, independència física, independència lògica, redundància, transacció, concurrència, seguretat, SQL, DDL, DML, DQL, model d'entitat relació.
