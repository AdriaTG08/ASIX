# Apunts: Gestió de Bases de Dades (1r ASIX)

## 1. Base de dades — conceptes bàsics

**Base de dades (BD):** conjunt organitzat de dades relacionades entre si, emmagatzemades de manera estructurada perquè es puguin consultar, modificar i gestionar de forma eficient.

### Dada vs Metadada

| | Dada | Metadada |
|---|---|---|
| Què és | El valor concret emmagatzemat | "Dades sobre les dades" — descriu l'estructura |
| Exemple | `Joan`, `25`, `2003-05-12` | Que "nom" és un `String`, que "edat" és un `Integer` |

> Idea clau: la metadada és el "manual d'instruccions" que explica com estan organitzades les dades reals (tipus, mida, restriccions...).

## 2. Tipus de dades

| Tipus | Descripció | Exemple |
|---|---|---|
| **String** | Cadena de text/caràcters | `"Girona"` |
| **Integer** | Nombre enter (sense decimals) | `42` |
| **SmallInt** | Enter més petit, ocupa menys memòria | `120` |
| **Float** | Nombre decimal (coma flotant) | `3.14` |
| **Numeric** | Decimal amb precisió exacta fixada | `1234.56` |
| **Alphanumeric** | Combinació de lletres i números | `"AB123"` |

> **Float vs Numeric:** Float és aproximat (útil per càlculs científics), Numeric és exacte (imprescindible per diners, per evitar errors d'arrodoniment).

### Domini i valor nul

- **Domini:** conjunt de valors vàlids que pot prendre un atribut (ex: domini de "mes" = 1-12).
- **Valor nul (NULL):** representa l'absència de valor — **no és el mateix que 0 o una cadena buida**, significa "desconegut" o "no aplicable".

## 3. Fases del disseny d'una base de dades

```
1. Disseny Conceptual → 2. Disseny Lògic → 3. Disseny Físic
```

| Fase | Què es fa | Resultat |
|---|---|---|
| **Conceptual** | Analitzar el problema real, identificar entitats i relacions | Model Entitat-Relació (E-R) |
| **Lògic** | Traduir el model conceptual a un model concret (ex: relacional) | Taules, claus, normalització |
| **Físic** | Implementar-ho en un SGBD concret | Base de dades funcionant (MySQL, PostgreSQL...) |

> Idea clau: es passa del **món real** (què necessito representar) → al **model conceptual/lògic** (com ho estructuro) → al **model físic** (com ho implemento realment en un motor de BD).

## 4. Del món real al model

- **Món real:** la situació o problema que volem representar (ex: una biblioteca).
- **Model conceptual:** representació abstracta d'aquest món (entitats, atributs, relacions), independent del SGBD.
- **Representació:** com es plasma aquest model (diagrames E-R, taules...).

## 5. Elements bàsics del model E-R

| Terme | Definició | Exemple |
|---|---|---|
| **Entitat** | Objecte o concepte del món real que volem representar | `Alumne`, `Curs` |
| **Instància** | Un cas concret d'una entitat | L'alumne `"Adrià"` |
| **Atribut** | Característica/propietat d'una entitat | `nom`, `edat` |
| **Valor** | Dada concreta que pren un atribut | `nom = "Adrià"` |
| **Enunciat** | Descripció textual del problema, punt de partida del disseny | "Volem gestionar alumnes i les seves notes" |

## 6. Claus (Keys)

| Clau | Definició |
|---|---|
| **Clau primària (PK)** | Atribut (o conjunt) que identifica de manera **única** cada fila d'una taula. No pot ser NULL. |
| **Clau forana (FK)** | Atribut que referencia la clau primària d'una altra taula, per crear relacions entre taules. |
| **Identificador** | Concepte general: allò que distingeix una instància de la resta (a la pràctica, sol ser la clau primària) |

**Exemple:**
```
Taula ALUMNE            Taula MATRICULA
id_alumne (PK)          id_matricula (PK)
nom                     id_alumne (FK) → referencia ALUMNE
```

> Idea clau: la clau forana és el "pont" que connecta dues taules i manté la integritat referencial (no pots matricular un alumne que no existeix).

## 7. Representació tabular

| Terme | Equivalent conceptual |
|---|---|
| **Taula** | Conjunt d'entitats del mateix tipus |
| **Fila (registre)** | Una instància concreta (un enunciat de dades complet) |
| **Columna (camp)** | Un atribut |
| **Cel·la** | El valor concret d'un atribut per a una fila |

```
        columna→  id | nom     | edat
fila→        1   | Adrià   | 18
fila→        2   | Marta   | 20
              ↑
            cel·la
```

## 8. Organització de fitxers/dades

Formes en què es poden emmagatzemar físicament els registres per accedir-hi:

| Organització | Com funciona | Avantatge | Inconvenient |
|---|---|---|---|
| **Seqüencial** | Els registres es guarden un darrere l'altre, en ordre | Molt eficient per llegir-ho tot seguit | Lenta per buscar un registre concret (cal recórrer-los tots) |
| **Directa (aleatòria)** | S'accedeix directament a la posició mitjançant una funció/clau (hash) | Accés molt ràpid a un registre concret | Pot generar col·lisions, difícil d'organitzar seqüencialment |
| **Indexada** | Es manté un índex (com el d'un llibre) que apunta a la posició dels registres | Combina rapidesa d'accés amb possibilitat de recórrer-ho ordenat | Cal mantenir l'índex actualitzat (cost extra en escriptures) |

> Analogia: 
> - **Seqüencial** = llegir un llibre pàgina a pàgina.
> - **Directa** = saber exactament a quina pàgina està el que busques i anar-hi directament.
> - **Indexada** = fer servir l'índex del llibre per trobar la pàgina, i després anar-hi.

---

**Idea clau general:** una base de dades ben dissenyada segueix un procés clar (conceptual → lògic → físic), on cada dada té un tipus i un domini definits, les taules es relacionen mitjançant claus primàries i foranes, i la manera d'organitzar físicament els registres (seqüencial, directa, indexada) determina la rapidesa amb què es pot accedir a la informació.
